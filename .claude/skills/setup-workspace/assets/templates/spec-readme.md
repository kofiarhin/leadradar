# Specifications

Specifications define the **technical contract** for an approved ticket.

Each spec should reference its source ticket and describe the relevant existing system, proposed solution, architecture/data/API/UI behaviour as applicable, validation, errors and edge cases, security/privacy concerns, affected areas, testing requirements, technical risks, and unresolved technical questions.

Inspect relevant repository code and tests before specifying the solution. Do not implement the feature while generating the spec.

Prefer the same basename as the source ticket, for example `spec/004-saved-products.md`.
